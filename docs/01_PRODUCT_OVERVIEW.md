# 1. Product Overview

## 프로젝트명

CRWALLM

## 한 줄 정의

**자연어 또는 직접 조작으로 크롤링 계획을 만들고, 정적/동적 웹에서 정형·반정형·비정형 데이터를 대량 수집하는 로컬 AI 크롤러.**

## 핵심 흐름

```text
자연어 요청  ──┐
               ├→ CrawlSpec / Recipe → Pydantic → Policy → 크롤러 → 추출 → 필터 → 저장
직접 작성    ──┘
```

두 입력 경로가 **동일한 산출물**을 만들고 **동일한 게이트**를 통과한다.
LLM에게 특권 경로는 없다.

## 해결하려는 문제

기존 크롤러는 사용자가 URL 구조, selector, 페이지네이션, 정적/동적 여부, 저장 구조를 직접 알아야 한다.
사이트가 바뀌면 selector를 손으로 고쳐야 한다.

CRWALLM은 목적만 기술하면 되도록 한다.

> "이 쇼핑몰의 노트북 상품명, 가격, 링크를 최대 500개 수집해."

동시에, **원할 때는 언제든 직접 조정할 수 있어야 한다.** LLM은 편의 레이어이지 필수 의존이 아니다.

## 핵심 차별점

### 1. LLM은 크롤러가 아니라 컴파일러/컨트롤 플레인

```text
LLM    = 계획 / 컴파일 / 적응 / 수리
크롤러 = 결정론적 실행
```

대량 페이지 수집에 LLM을 태우지 않는다. 비용과 재현성이 이유다.

### 2. 결정론 우선, LLM은 그다음

LLM을 부르기 전에 코드로 먼저 시도한다.

```text
결정론적 구조 탐지  →  성공하면 LLM 0회
        ↓ 실패
로컬 LLM (N-후보 + 채점 + 재시도)
        ↓ 실패
클라우드 API (어려운 사이트만)
```

### 3. Recipe 재사용

```text
사이트 1회 이해 → Recipe → 100 / 10,000 / 100,000 pages → LLM 0회
```

구조 지문(fingerprint)이 일치하면 도메인이 달라도 기존 Recipe를 먼저 시도한다.

### 4. 정책 우선순위

```text
System Policy  >  CrawlSpec  >  LLM Suggestion
```

LLM은 크롤링 범위를 임의로 넓힐 수 없다.

### 5. 로컬 완결

모델도 데이터도 기기 밖으로 나가지 않는다(로컬 LLM 사용 시). 토큰 비용 0.
GPU가 부족하면 클라우드 API로 전환하거나, LLM 없이 수동 조작으로 사용한다.
